## 1. 项目定位

本项目是一个**本地可运行的学生学业发展评价分析系统原型**，核心是使用规则空间模型（Rule Space Model, RSM）对学生学业发展状态进行可解释诊断。

当前阶段的系统定位是：

- 以网页形式在本地运行。
- 支持 Excel / CSV 数据导入。
- 自动完成数据校验、缺失值填补、标准化、AHP 权重聚合、RSM 诊断、结果可视化和报告导出。
- 服务于课题展示、模型验证和校内小范围试点。
- 不开发学生端、教师端、学校端三类门户。
- 不开发复杂权限体系。
- 不做生产级高并发部署。

项目优先追求：

1. **可运行**：普通 Windows 电脑能启动。
2. **可解释**：教师能看懂每个学生为什么被评为某一等级。
3. **可展示**：课题中期、结题、汇报时能演示完整流程。
4. **可扩展**：后续能加入学科 Q 矩阵、SQLite 历史记录、PDF 报告等功能。

## 2. 当前技术栈

保持轻量，不要引入复杂框架。

| 层级 | 当前实现 | 开发要求 |
|---|---|---|
| 后端 | Python + Flask | 保持单体本地应用，不改成大型微服务 |
| 数据处理 | Pandas + NumPy | 保持可解释的数据清洗、标准化、聚合逻辑 |
| 模型 | 简化规则空间模型 RSM + AHP 权重 | 不要改回随机森林、GBDT 等黑箱主模型，除非用户明确要求做对比实验 |
| 前端 | Jinja2 模板 + 本地 CSS + Canvas 图表 JS | 优先保持本地资源，避免学校内网环境下 CDN 失效 |
| 数据文件 | CSV / XLSX / XLS | 保留模板下载、上传分析、导出报告 |
| 输出 | CSV、JSON、XLSX | 后续可增加 PDF，但不要破坏现有导出 |

推荐 Python 版本：`3.10+`。

## 4. 模型与业务边界

### 4.1 三类一级指标

系统当前围绕三类一级指标计算综合评价：

1. **成绩波动趋势**：权重 `0.35`
2. **知识点掌握度**：权重 `0.35`
3. **学习行为活跃度**：权重 `0.30`

权重配置来自 `config/indicators.json`，修改权重时必须同步检查：

- 一级权重之和是否为 1。
- 二级权重在所属一级指标下是否合理。
- 三级指标权重在所属二级指标下是否合理。
- 缺失指标时是否会自动按可用指标重算权重。

### 4.2 九个规则空间属性

当前 RSM 把 9 个二级指标视作属性空间：

1. 基础成绩水平
2. 成绩波动幅度
3. 进步退步幅度
4. 知识点达标率
5. 知识点应用能力
6. 课堂互动行为
7. 作业提交行为
8. 在线学习行为
9. 自主学习行为

每个属性根据二级指标得分转为：

```text
1 = 掌握
0 = 未掌握
```

默认掌握阈值：

```text
mastery_threshold = 65
```

### 4.3 合法理想状态约束

不要随意删除这些约束。它们是当前 RSM 可解释性的核心。

当前约束逻辑：

```text
知识点应用能力 = 1 时，知识点达标率必须 = 1。
进步退步幅度 = 1 时，基础成绩水平或知识点达标率至少一个 = 1。
自主学习行为 = 1 时，在线学习行为或作业提交行为至少一个 = 1。
```

如要调整这些规则，必须在代码注释和 README 中说明调整原因。

### 4.4 核心输出指标

当前模型输出应至少保留：

| 字段 | 含义 |
|---|---|
| 综合评分 | 基于 AHP 权重的综合分 |
| RSM调整分 | 综合评分、Theta、Zeta 结合后的调整分 |
| 学业等级 | 优秀、良好、中等、待提高、需帮扶 |
| 发展潜力 | 快速进步、稳步进步、波动观察、潜力待激发、学业预警 |
| 规则空间Theta | 属性掌握度，越高越好 |
| 规则空间Zeta | 与最近理想状态的偏离度，越低越稳定 |
| 最近理想状态 | 当前属性模式最接近的理想状态等级 |
| 薄弱属性 | 得分最低或未掌握的关键属性 |
| 建议摘要 | 基于薄弱属性生成的干预建议 |

当前 RSM 调整分公式：

```text
RSM调整分 = 0.80 × 综合评分 + 0.10 × Theta + 0.10 × (100 - Zeta)
```

如要修改公式，必须：

1. 保留旧公式注释。
2. 在 README 中说明新公式。
3. 增加或更新测试用例。
4. 确认前端展示文案同步更新。

### 4.5 学业等级阈值

当前等级：

```text
优秀：85 分及以上
良好：70-84 分
中等：55-69 分
待提高：40-54 分
需帮扶：40 分以下
```

等级阈值在 `config/indicators.json` 中维护，不要在多个代码文件里重复硬编码。

## 5. 数据处理要求

### 5.1 输入数据

系统支持：

```text
.csv
.xlsx
.xls
```

基本字段建议保留：

```text
学号
姓名
班级
学科
```

如果缺少基本字段，系统当前会自动生成默认值。不要删除此兼容逻辑。

### 5.2 指标字段

完整指标体系包含 35 项三级指标。系统允许用户只上传部分指标，但必须做到：

- 自动识别可用指标。
- 对不可识别字段不直接报错。
- 在日志中提示识别到多少个标准字段、多少个可用指标。
- 没有任何指标字段时才报错。

字段别名统一维护在：

```text
config/indicators.json -> aliases
```

不要把别名分散写在 `app.py`、前端模板或其他文件中。

### 5.3 异常值处理

当前约定：

- 百分制成绩类指标范围为 `[0, 100]`。
- 趋势类指标范围为 `[-100, 100]`。
- 次数、时长、数量等非负指标不能小于 0。
- 异常值先置为缺失，再参与缺失填补。

### 5.4 缺失值填补

当前优先级：

```text
班级 + 学科 + 指标 中位数
→ 学科 + 指标 中位数
→ 全局中位数
→ 0
```

不要改成均值优先，除非用户明确要求。中位数对极端值更稳健，更适合当前原型。

### 5.5 标准化

当前输出两类标准化结果：

1. `0-100` 评分，用于模型计算。
2. `Z_指标名` 审计列，用于导出和查看标准化过程。

注意：课题材料中有 Z-score 标准化思路，当前代码同时保留 0-100 评分和 Z-score 审计列，目的是兼顾计算可解释性和过程审计。

## 8. 编码规范

### 8.1 Python

- 使用类型注解。
- 保持函数短小，优先让模型逻辑集中在 `models/rsm.py`。
- 路由层 `app.py` 只处理请求、响应、文件保存、模板渲染，不承载复杂模型逻辑。
- 新增模型逻辑时优先写纯函数，方便测试。
- 不要吞掉异常后完全不提示。面向用户的异常要简洁，日志要保留具体原因。
- 不要把真实学生数据、身份证、手机号等个人信息写进代码、测试或演示数据。

### 8.2 前端

- 页面语言使用中文。
- 教育术语保持一致：
  - 学业等级
  - 发展潜力
  - 规则空间Theta
  - 规则空间Zeta
  - 薄弱属性
  - 建议摘要
- 保持本地可用，尽量不依赖 CDN。
- 新增图表时优先复用 `static/charts.js`，不要引入大型前端构建工具。
- 不要把界面改成多端门户，当前只需要“分析系统”。

### 8.3 配置

- 指标、权重、阈值、字段别名统一写入 `config/indicators.json`。
- 不要在模板或 JS 中重复维护权重。
- 改动配置时，必须保证 `/config` 能正常返回 JSON。

## 9. 隐私与数据安全

这是教育数据项目，必须谨慎处理学生数据。

开发时遵守：

1. 不提交 `uploads/` 和 `output/` 中的真实数据。
2. 演示数据必须是合成数据。
3. 测试数据不得包含真实姓名、身份证号、手机号、家庭住址等敏感信息。
4. 导出的报告只作为本地分析结果，不自动上传任何外部服务。
5. 不添加云端同步、第三方统计脚本或远程日志上报。
6. 如需保存历史数据，默认保存在本地 SQLite。

```text
5. 应用启动时执行校验，发现问题时给出明确错误提示。
6. 增加测试覆盖正常配置和异常配置。
```
